# Mandala — Plan d’internationalisation (i18n)

> **Statut :** proposition · **Date :** 2026-11-01  
> **Repo :** `eludinart/workspace-mandala`  
> **Contexte :** UI 100 % FR aujourd’hui ; ~110 écrans/composants TSX, dates en `fr-FR`, pas de `next-intl` / catalogues.  
> **Objectif utilisateur :** EN (UK), DE, ES, IT + extension monde ; estimations en **jours-homme (jh)**.

---

## 1. Périmètre langues

### Vague 1 (minimum demandé)

| Code | Langue | Marché prioritaire |
|------|--------|-------------------|
| `fr` | Français (source) | FR / BE / CH / francophonie |
| `en-GB` | English (UK) | Royaume-Uni + fallback international |
| `de` | Deutsch | DE / AT / CH |
| `es` | Español | ES + LATAM (variante neutre v1) |
| `it` | Italiano | IT / CH |

**5 locales** (FR source + 4 cibles).

### Vague 2 (extension « monde »)

Par ordre de ROI probable pour lieux / pratiques :

1. `pt-BR` (Brésil)  
2. `nl` (Pays-Bas / Flandre)  
3. `en-US` (variante US si besoin copy/legal séparée)  
4. `pl`, `cs` (Europe centrale)  
5. `ja`, `ko` (Asie — plus cher : QA + légal)  
6. `ar` (RTL — chantier à part, +40–60 % coût)

**Règle :** une langue n’entre en prod que si (a) catalogue UI complet, (b) légal traduit ou disclaimer « FR fait foi », (c) smoke QA natif ou bilingue.

## 3. Architecture technique recommandée

**Choix :** `next-intl` (App Router Next 15) + messages JSON/TS par locale.

### Principes

1. **FR = source de vérité** des clés (`messages/fr.json`).  
2. Locale utilisateur : préférence compte (`usermeta`) > `Accept-Language` > défaut `fr`.  
3. Routes publiques : option `[locale]` (`/en-GB/cgu`) ou query/`cookie` — **recommandation** cookie + `NEXT_LOCALE` pour ne pas casser `/app` PWA / TWA.  
4. Serveur : erreurs métier → `error_code` ; libellé côté client. Exceptions e-mails / webhooks : templates localisés.  
5. Pas de Google Translate auto en prod sans relecture (qualité lieux / spirituel / légal).

### Outillage

- `next-intl` + ESLint plugin (clés manquantes)  
- Script extract / check coverage  
- CI : fail si locale cible < 98 % des clés FR  
- Glossaire : `docs/i18n/GLOSSARY.md` (lieu, Mandala Pro, lieu ami…)

**Estimation socle technique (wiring, helpers date/number, préférence langue, CI) :** **8–12 jh**

## 5. Détail des chantiers sensibles

### 5.1 Dates & fuseaux

Aujourd’hui : **heure murale** des événements (18:05 = 18:05 affichée partout).  
**Recommandation v1 i18n :** conserver ce modèle + formater avec `Intl` selon locale (ordre jour/mois, noms de mois).  
**v2 (optionnel, +8–15 jh) :** TZ IANA par lieu (`Europe/Paris`, `Asia/Kolkata`) — migration données + UX « fuseau du lieu ».

### 5.2 Monnaie & Stripe

- Catalogue actuel : EUR (29 / 12 €).  
- Options :
  1. **Rester EUR partout** + affichage localisé (« 29,00 € ») — simple (**+1–2 jh**).  
  2. **Prix Stripe par devise** (GBP, CHF, USD…) + mapping `STRIPE_PRICE_*_{CCY}` — (**5–8 jh** inclus ligne I).  
  3. Stripe **Adaptive Pricing** / currency conversion — moins de price_id, plus de dépendance Stripe.

Play Billing : SKUs / prix par pays gérés **dans Play Console** (travail ops, peu de code).

### 5.3 Légal

- Traductions « informationnelles » + clause **« En cas de divergence, la version française fait foi »** (réduit le risque avocat ×4).  
- Si contrats B2B Lieu hors UE : faire valider par conseil (**hors jh dév**, budget légal séparé ~2–5 k€ selon pays).

### 5.4 UGC & modération

- Motifs de signalement traduits.  
- Contenu utilisateur **non traduit**.  
- Modération : process FR/EN au minimum (équipe).

```
A Audit/glossaire
 → B Socle next-intl
 → C Extraction UI (FR keys)
 → D Erreurs API
 → E Traductions EN-GB d’abord (pivot)
 → E’ DE / ES / IT en parallèle
 → F E-mails
 → G Légal
 → I Stripe devise (si pas « EUR only »)
 → H Play listings
 → J QA
```

**Porte produit :** ne pas exposer le sélecteur de langue au public tant que EN-GB n’est pas QA-vert (`MANDALA_I18N_PUBLIC=0` analogue billing).

## 7. Risques principaux

| Risque | Impact | Mitigation |
|--------|--------|------------|
| Volume de littéraux sous-estimé | Dérapage +30–50 % extraction | Audit A chiffré + CI coverage |
| Vocabulaire « lieu / Mandala Pro » mal traduit | Confusion produit | Glossaire verrouillé avant DE/ES/IT |
| Heure murale vs fuseaux | Bugs événements internationaux | Décision écrite v1 ; TZ en v2 |
| Multi-devise Stripe mal synchronisée | Double facturation / prix faux | EUR-only v1 ou matrix price_id testée |
| Légal traduit non opposable | Litige | Clause FR fait foi + avocat si marchés ciblés |
| Play / App Store politiques par pays | Rejet fiche | Listings + Data safety par locale |
| Qualité machine translation | Ton « IA » / erreurs spirituelles | Relecture native obligatoire |
| Maintenance 5+ langues | Dette continue | Budget **~1–2 jh / mois** après Vague 1 |
| TWA / PWA `start_url` | Locale perdue au lancement | Cookie locale + `lang` manifest dynamique |
| Contenu lieux (chartes) en FR seulement | UX inconsistante | Clarifier : UGC = langue auteur |
